# 低 Ratio 迷宫深度诊断（含 Reward 分项分析）

**测试算法**：贪心（Dinkelbach surrogate reward）+ 3×3 局部视野
**测试集**：train_0001 ~ train_0200（200 个迷宫）
**平均 ratio**：1.97

---

## 一、Reward 公式速查

```
Score = ΔR + ω_I·α_smooth·I_proxy + β·V_tail − q_eff·len − φ_margin
φ_margin(r) = λ_m · max(0, m_safe−r)² / m_safe²      ; λ_m=8, m_safe=30
q_eff = max(q_ref, q_min)                               ; q_min=1.0
I_proxy = κ_u · min(E, A_max) · clip(max(v_area,0)/50, ρ_area_min, 1)
α_smooth ∈ [1, 8], 初始 ≈4.0
```

## 三、逐个深度诊断

### 🔴 train_0076 — 死胡同振荡死循环

**Reward 数据追踪**：

```
Step 0: S=(0,1)  α=4.67  qEff=1.00
  (1,1)=G:  score=100.62  dR=50  I=63.0  tail=0  len=1  mar=0  pR=50  ← 选中
  (1,2)=·:  score=99.80   dR=50  I=63.0  tail=0  len=2  mar=0  pR=50

Step 1: (1,1)=G  α=5.20  qEff=25.00  ← RE 吃完金币
  (1,2)=·:  score=27.82   dR=0  I=53.1  tail=0  len=1  mar=0  pR=50  ← 选中
  (2,1)=·:  score=27.82   dR=0  I=53.1  tail=0  len=1  mar=0  pR=50

Step 4: (2,1)=·  α=5.85  qEff=10.00
  (3,1)=T: score=-33.19  dR=-30  I=5.8  tail=0  len=1  mar=0.9  pR=20  ← 选中!!
  (1,3)=T: score=-49.59  dR=-30  I=5.8  tail=0  len=3  mar=0.9  pR=20
  (2,3)=·: score=-57.79  dR=-30  I=5.8  tail=0  len=4  mar=0.9  pR=20

Step 9: (7,1) 死胡同!  α=6.26  qEff=2.00  decision=FALLBACK
  (1,3)=T: score=-1e18   dR=-30  I=3.6  tail=0  len=8  mar=0  pR=-10  ← 全部非法!
  (2,3)=·: score=-1e18   dR=-30  I=3.6  tail=0  len=9  mar=0  pR=-10
```

**逐步解释**：

1. **Step 0**：金币 (1,1) 得分 100.62。dR=50 贡献 50，I_proxy=63 贡献 0.4×4.67×63≈117，减去 qEff×1=1。注意 (1,2) 的 dR=50 是因为路径 [(0,1),(1,1),(1,2)] 途经金币。AI 选择了更短的 (1,1)。

2. **Step 1**：吃完金币 R=50，qEff 骤升到 25。I_proxy 从 63 降到 53（因为 3×3 视野扩大后新可见格减少）。dR=0（格子都是空格）。Score = 0 + 0.4×5.2×53.1 − 25×1 = 27.82。

3. **Step 4**：从 (2,1) 出发，唯一的未访问格是 (3,1)=T 和 (1,3)=T。所有候选 dR=−30。AI 选最近的那个 (3,1)。此时 pR=20（R=50 减去陷阱 30）。

4. **Step 5-8**：从 (3,1) 继续南下到 (7,1)。I_proxy 从 5.1 跌到 3.9（走廊窄，BFS expansion 只找到越来越少的未观察格）。但 R=20 让 margin penalty 给了 0.9（(30−20)/30=0.33, 平方×8=0.89），加上 qEff（3.33→2.22），总分勉强正（1.73 到 1.51）。

5. **Step 9**：(7,1) 死胡同。仅剩的两个候选 (1,3) 和 (2,3) 都需穿过 (3,1)=T（已触发不算分），但到它们路径很长（len=8/9）。从 (7,1) 出发的路上还有哪些陷阱？从 (7,1)→...→(3,1) 已经触发，所以 deltaR=0。但 projectedR=20+0-30=-10（因为路径上还包含 (1,3)=T 或穿过它），所以 pR=−10 → 非法。

6. **Step 9-900**：fallback 把 AI 拉回上一格 (6,1) → (5,1) → ... → 最终在 (0,1)↔(1,1) 之间振荡 445 次。因为这两个格子是已知地图中唯二 "walkableForPlanning=true 且 pR≥0 且 score 不是 -1e18" 的候选。

**根因**：`projectedResource < 0` 的硬约束在 R=20 时太容易触发了。任何路径如果途经未触发的陷阱 (1,3)=T，总资源就变成 −10 → 非法。而 (1,3) 恰好是通向南侧更大区域的必经之路。AI 被困在走廊中，无法绕行。

**改进方案**：
- **硬约束放软**：将 `projectedR < 0` 的硬约束从 -1e18 降为大的负惩罚（如 -1e6），允许 AI 在紧急情况下"赌一把"
- **分阶段搜索**：先搜无陷阱路径 → 没有时搜含 1 个陷阱的路径 → 仍没有时搜含 2 个的
- **maxSteps 硬顶**：当总步数超过迷宫大小的 3 倍仍未到出口时强制停止
- **候选为空时判断**：连续 N 步无有效候选时，直接沿已知地图向最接近的未观察边界移动

### 🔴 train_0181 — R=0 开局 margin penalty 主导

**Reward 数据追踪**：

```
Step 0: S=(0,1)  R=0  α=4.62  qEff=1.00
  (1,1)=·: score=5.74   dR=0  I=18.0  tail=0  len=1  mar=8.0  pR=0  ← 选中

Step 10: (1,10)  R=0  α=6.88  qEff=1.00
  (1,11)=·: score=-1.28  dR=0  I=6.3  tail=0  len=1  mar=8.0  pR=0  ← 全部负数!

Step 40: (5,8)  R=0  α=6.33  qEff=1.00
  (5,9)=·: score=-8.02   dR=0  I=0.7  tail=0  len=1  mar=8.0  pR=0  ← I_proxy 已跌到 0.7

Step 70: (9,12)  R=0  α=5.64  qEff=1.00
  (9,13)=G: score=49.89  dR=50  I=0.7  tail=0  len=1  mar=0  pR=50  ← 终于是金币!!
```

**逐步解释**：

1. 开局 R=0。**margin penalty = 8.0 × ((30−0)/30)² = 8.0**。去掉 margin 后，score=5.74+8=13.74，还算正常。但 margin=8.0 把大量候选压成接近零甚至负数。

2. Step 0：dR=0 + 0.4×4.62×18 − 1×1 − 8 = 5.74。I_proxy=18.0 是关键——它能抵消大部分 margin。但 I_proxy 在走廊中剧烈衰减。

3. Step 10：I_proxy 已从 18 跌到 6.3（因为走廊只能看到左右各 1 格，背后没有新区域）。score=−1.28，已经变负。AI 在选"最不差的负数方案"。

4. Step 40：I_proxy 跌至谷底 0.7。此时信息价值贡献仅 0.4×6.33×0.7=1.77，完全无法抵消 margin=8.0。score=−8.02。

5. **关键问题**：在 R=0 的整整 70 步中，AI 一直在捡负数分的候选。它在做什么？在沿着走廊盲目推进——不是因为看到了金币，而是因为每步 score 都是"当前可达候选中最不差的"。

6. Step 70：终于在 (9,13) 发现金币！score=49.89（dR=50 支配一切，margin 归零因为 pR=50≥30）。

7. Step 78：找到出口，exit 触发（bestScore=−0.13 ≤ τ=5.0 ∧ obs=0.60 ≥ ρ_min=0.25）。

**根因**：R=0 时 margin=8.0 对所有候选施加了均匀的 -8 惩罚，淹没了奖赏信号。AI 在找金币的路上被迫走过 70 步"负数分"的路径，最终只捡到 1 枚金币就在出口离开。

**改进方案**：
- **R=0 时 margin 减半**：初始阶段 margin 太大，`λ_m` 应随 R 变化而非固定 8
- **允许回溯搜索**：AI 在 (1,10) 发现前方无金币但 I_proxy=0.7 时，应能考虑回到 (1,1) 并尝试不同的分叉方向。目前回退路径的 len 更高、score 更负，永远不会被选中
- **I_proxy 设计缺陷**：在窄走廊中 I_proxy 快速衰减但走廊尽头可能有大片区，当前 BFS expansion 无法"看穿"走廊

### 🟡 train_0084 — I_proxy 衰减 + margin 压制

**Reward 数据**：

```
Step 0:  score=5.74  (同 train_0181)
Step 10: score=-10.42 dR=0  I=0.7  len=4  mar=8.0  ← R=0, I_proxy 已枯竭
Step 30: score=12.61  dR=0  I=12.7  len=1  mar=8.0  ← I_proxy 在分叉口短暂回升
Step 60: score=2.82   dR=0  I=3.7   len=1  mar=8.0
Step 66: EXIT  score=2.38 (best≤τ=5)
```

和 train_0181 类似，但 I_proxy 在 Step 30 分叉口短暂回升到 12.7（新方向打开了更大的未观察区域）。这证明了 I_proxy 的价值——当 AI 到达分叉口时，BFS expansion 能探测到更多未观察格。

但最终 AI 只捡了 2 枚金币（R=70），exit 触发时 ratio=1.03。

### 🟡 train_0143/0073/0122 — 陷阱必经路径

共同特征：陷阱在关键通道上，AI 必须穿过它们才能到达金币。AI 的正确做法是穿越陷阱（因为绕路代价更大），但问题是陷阱的 -30 没有被任何"风险预算"机制对冲。

**改进方案**：
- 对每一段含陷阱的路径，评估绕路代价 vs 陷阱损失。如果绕路代价 ≤ 30，选绕路路径
- 如果绕路代价 > 30，陷阱不可避免，则不过度惩罚（当前正则化没有问题）

## 五、改进方案（按优先级）

### P0：死循环保护
- 连续 10 步 decision=fallback 且未观察到新格子 → 强制 break
- 全局 maxSteps = 2 × 可走格数（约 2×120=240）

### P1：R=0 时 margin 缩放
```cpp
double effectiveMargin = parameters_.lambdaMargin
    * sqr(max(0, safeResource - projectedR) / safeResource);
if (context.state.resource == 0) effectiveMargin *= 0.3;  // R=0 时 margin 降到 2.4
```

### P2：候选全部非正分时切换策略
当 `max(bestScore) ≤ 0` 时，不再依赖 reward 排序，改用 `min(len) + max(I_proxy/len)` 二段排序，让 AI 朝能扩大视野的区域走。

### P3：陷阱绕路评估
在 `shortestPathOnKnownMap` 中加入无陷阱版本；比较绕路代价和陷阱损失。

### P4：I_proxy 走廊穿透
在 BFS expansion 中允许穿透窄走廊先看后面有多大的未知区域（2-3 步深度搜索代替当前逐格 BFS）。

### P5：qEff 在 R=0 时设合理默认值
当前 `qEff = max(R/ε, 1.0) = 1.0`。可考虑用已知金币密度估计一个"预期步数价值"，如 `qEff = max(50 * rho_G, 1.0)`。
