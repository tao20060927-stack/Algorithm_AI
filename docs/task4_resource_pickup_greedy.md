# Task4 第一问：3x3 资源拾取贪心算法说明

## 任务目标

输入一个 3x3 网格，玩家从 `P` 出发，只能上下左右移动。金币 `G` 记 `+50`，陷阱 `T` 记 `-30`，空地 `.` 记 `0`。同一个 `G/T` 只在第一次经过时触发一次，之后重复经过不再加分或扣分。

算法目标是让最终：

```text
资源/路程 = R / L
```

尽量大。玩家可以随时停止，不要求吃掉所有金币。

## 贪心候选

每一轮从当前格子出发，把当前格以外的其它可走格都作为候选目标。也就是在普通 3x3 输入中，最多有 8 个候选格子。

对每个候选格子 `t`，不只看一条路径，而是枚举：

```text
从当前位置到 t 的所有最短路径
```

每条最短路径都会计算走完后的投影比值：

```text
score(path) = (R + DeltaR(path)) / (L + len(path))
```

其中：

- `R`：当前已经获得的资源值；
- `L`：当前已经走过的步数；
- `DeltaR(path)`：这条最短路径上新触发的金币和陷阱总和；
- `len(path)`：这条最短路径的步数。

候选格 `t` 的 reward 定义为：

```text
Reward(t) = max score(path)
```

也就是所有最短路径中，走到 `t` 之后 `R/L` 最大的那一条路径。

## 清理度

如果两个候选路径的 `R/L` 相同，就比较第二优先级：清理度。

清理度定义为：

```text
cleanup(path) = 路径中新触发的每个陷阱周围相邻金币数量之和
```

只统计上下左右相邻的金币。已经触发过的陷阱再次经过时不再增加清理度。

清理度的作用是：当多个路径的 `R/L` 一样时，优先选择清理更关键陷阱的路径。

## 移动规则

每一轮选择 reward 最大的候选格。如果多个候选 reward 相同，按以下顺序打破并列：

```text
1. Reward(t) 更大
2. cleanup 更大
3. DeltaR(path) 更大
4. 路径更短
5. 坐标顺序更靠前
```

如果选中的候选满足：

```text
Reward(t) >= 当前 R/L
```

并且这条路径至少触发一个新的 `G/T`，玩家就沿该最短路径移动过去。

如果没有这样的候选，玩家原地停止。

## 为什么要求“触发新资源”

如果 3x3 全是空地，那么所有空地候选的投影比值都是：

```text
0 / L = 0
```

它们会满足 `Reward >= 当前 R/L`。如果允许这种路径驱动移动，玩家会在空地之间无限来回走。

因此实际移动必须满足：

```text
路径至少触发一个新的 G/T
```

不触发新资源的候选仍然可以显示 reward，但不能让玩家继续移动。

## 输出结果

后端输出包含：

- `path`：最终路径；
- `frames`：逐步播放帧；
- `resource`：最终资源值；
- `steps`：最终步数；
- `score_ratio`：最终 `R/L`；
- `greedy_rounds`：每一轮的候选格 reward、清理度、路径和是否被选中。

## 示例

接口样例：

```json
{
  "case_id": 2,
  "grid": [
    [".", "T", "G"],
    [".", "P", "T"],
    [".", "T", "G"]
  ]
}
```

第一轮从 `P=(1,1)` 出发，候选 `(0,2)` 和 `(2,2)` 都能通过最短路径获得：

```text
R/L = 20 / 2 = 10
```

其中经过 `(1,2)` 陷阱的路径清理度更高，因为该陷阱相邻两个金币。因此算法先走：

```text
(1,1) -> (1,2) -> (0,2)
```

之后再走：

```text
(0,2) -> (1,2) -> (2,2)
```

最终结果：

```text
资源 = 70
步数 = 4
比值 = 17.5
```
